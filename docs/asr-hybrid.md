# 叙华双路 ASR（开发工作区）

## 目标和接口

同时使用讯飞方言大模型（`language=zh_cn`、`accent=mulacc`、`domain=slm`）与多语种大模型（`language=mul_cn`、`accent=mandarin`、`domain=slm`）。两者均连接 `wss://iat.cn-huabei-1.xf-yun.com/v1`，使用 16 kHz、单声道、16-bit PCM 数据。

多语种请求设置 `ln=zh|en|ja|ko`，将自动识别范围限定为中英日韩四种语言；方言模型覆盖普通话、英文和 202 种中文方言。实际可用服务取决于讯飞账号开通的产品和配额。

## 流程

浏览器 VAD 产生一段音频后，服务端的 `HybridXfyunStream` 同时启动两条独立识别连接，向两者转发相同的 PCM 音频。以多语种模型提供的 `lg` 判断语言：中文优先使用方言模型完成最终转写，其余语言使用多语种模型；当 `lg` 不可用时，以中文字符特征作为保守后备判断。只有一个模型成功时采用仍可用的结果。

浏览器/后端保留既有的单个逻辑流，保持 `finish_result()`、`send_audio()`、`close()`、取消/打断/转写事件的接口。最终结果需等待两路已启动的识别连接完成；部分转写可能在选择模型后发生修正。

## 限制、成本与后续验证

- 双路方式通常令每段音频产生两次上游识别请求，增加配额消耗和供应商侧并发要求；应用侧 `ASR_MAX_CONCURRENCY` 目前计数为逻辑语音段数。
- 上游可能对不同模型分别授权。单路故障时会回退；双路均失败时按原有语音错误机制处理。
- 对中文/方言的最终选择依赖多语种模型的语言判断；不同口音和多语言混说仍可能误判。需要普通话、河南话、四川话、粤语、英语、日语、韩语及其他语种真实录音测试。
- 当前仅启用中、英、日、韩四语种候选。四种同时启用超过讯飞官方建议的最多三种，需要实测识别准确率及串扰；回答语言及 TTS 仍单独受现有语音档案约束。
- PC 工作区更改不会自动部署到腾讯云，生产环境仍保持发布版。
