# Persona 讯飞唤醒接入设计

日期：2026-10-19。状态：已按本方案实施；真人识别率基线待采集。

## 1. 接入范围与现状

首版接入 Persona 展示页，以一台展示终端为目标。

核对结果：云端叙华 v0.2.4 为 healthy；`xfyun-wake` 为 active、引擎 ready，当前测试词仍是“小白小白”。Persona 已有本地 Sherpa 检测、固定“小露：我在。”音频，以及回答结束后 7 秒休眠的逻辑。

沿用现有对话、字幕、打断和休眠流程，新增讯飞云端检测适配器。检测方式通过服务端配置选择，保留现有 Sherpa 实现供回滚使用，同一时间只运行一种检测器。

## 2. 用户流程

1. 用户第一次点击右下角麦克风，允许采音，并解锁音频播放。已取得权限仍需确认音频上下文已运行；准备完成后才显示待机。
2. 待机提示“叫我叙华”，麦克风按钮保持轻微亮起。待机声音发送至云端讯飞唤醒服务，不调用 ASR 或大模型。
3. 喊“叙华”后，收到有效唤醒事件，播放已缓存的小露“我在。”；并行连接现有 `/api/voice`。
4. 对话连接确认就绪后提示“我在听”，后续走现有 ASR → AssistantService / DeepSeek → 讯飞 TTS。
5. 回答播完后仍可直接追问。连续 7 秒没有活动，关闭对话连接，恢复唤醒待机；刚唤醒但没提问也要有同样的超时退出。
6. 点击关闭语音，释放麦克风与连接，停止播放和重试。离开页面同样释放。

默认词拟设为“叙华”，同时提供“你好叙华”作为较长的备选词。两种词需用真人录音测试门限；当前“小白小白”的通过结果不能证明“叙华”的识别率。

## 3. 链路与职责

```text
一个浏览器麦克风采集源（AudioWorklet）
  ├─ 待机：PCM16 / 16 kHz → /api/wake → 内部 xfyun-wake → SDK
  │                                            ↓ 命中事件
  │                           本地播放“我在。”＋建立对话连接
  └─ 对话：VAD → /api/voice → 讯飞 ASR → 现有助手 → 讯飞 TTS
```

- `/api/wake` 是拟新增的叙华后端代理；浏览器使用同源连接。后端向内部唤醒服务认证，浏览器不持有讯飞凭据或独立测试页的长期访问码。
- 唤醒服务继续作为宿主机 systemd 服务运行，保留现有设备身份和授权缓存。
- 浏览器统一持有采集源，只切换音频去向。当前检测器和对话连接分别拥有媒体控制器，实现时需增加借用/释放边界，避免切换时关闭仍在使用的麦克风。
- 命中后立刻停止给唤醒引擎发送音频，忽略该检测会话的重复、迟到事件。对话和播报期间不检测唤醒，打断仍沿用现有 VAD/ASR 路径。
- 切换期间用最多 2 秒的内存音频缓冲承接提问开头。唤醒前的缓冲按 SDK 词尾位置裁剪，映射需用录音验证；缓冲按原顺序进入现有 VAD/ASR，不盲目重放整段唤醒词。连接失败或缓冲溢出时丢弃并提示重说，不把残句当完整问题。
- “我在。”由浏览器现有输出控制器播放、可被打断，人物说话状态跟随实际播放。该路径不再发送只为生成相同应答的旧 `wake` 命令，避免重复播报；其他旧客户端仍兼容原命令。唤醒提示不新增模型对话历史。

## 4. 状态与页面提示

| 状态 | 页面提示 | 行为 |
| --- | --- | --- |
| 关闭 | 点击开启语音 | 不采音、不重连 |
| 准备 | 正在准备语音 | 请求权限、预热音频、连接引擎 |
| 待机 | 叫我叙华 | 音频只送唤醒检测 |
| 命中并切换 | 我在，正在连接… | 播固定应答，暂存提问开头 |
| 对话 | 我在听 / 正在思考 / 正在回答 | 沿用现有语音状态 |
| 恢复 | 连接中断，正在恢复… | 暂停采音上传，有限退避重连 |
| 不可用 | 麦克风未授权 / 语音服务被占用 / 点击重试 | 允许文字提问，不显示假待机 |

只在现有麦克风按钮附近加简短提示，沿用全屏人物和底部两轮半透明字幕。用户关闭后，无论迟到回调或重连计时器都不能重新采音。麦克风权限或自动播放受限时，保留点击恢复入口。

## 5. 测试服务升级要求

- 当前 120 秒断开是测试限制。正式待机改用心跳及连接失活清理，保持长时间监听；失活后释放会话，重新进入待机时重置 SDK 识别状态。
- AIKit 官方文档明确该能力不支持多实例并发。首版按单展示终端设计：同一原生引擎只接收一个终端的音频；另一个页面提示占用，禁止混入另一人的音频。
- 待机入口需受展示终端访问权限保护，普通页面访问不自动抢占引擎。独立测试页与正式入口共用占用控制，正式终端启用时测试页不能抢占。
- 原始 PCM 为每秒 32 KB，连续待机约 115 MB/小时上行。这个版本依赖浏览器到云端的持续联网；后续玩偶端可另行评估把 SDK 放在设备上。
- 不保存原始录音，缓冲仅留在内存；关闭、失败或页面退出即清空。访问控制和重连不使用硬编码到前端的长期密钥。

## 6. 测量与验收

新增两个独立指标，使用浏览器同一单调时钟计时，不能把跨机器时间戳直接相减：

- 唤醒回应：SDK 报告的词尾映射到采集时间后，计算到“我在。”实际 `playing` 的时间；同时保留命中事件到播放的耗时。
- 普通问答：最后语音活动结束到回答实际 `playing`。唤醒应答与普通问答分开统计，报告成功数、失败数和 P50/P95。

验收包括：真人说两种唤醒词、普通聊天不应答、连续多次唤醒只播一次、唤醒后立即提问不丢字、无人提问自动回待机、播完 7 秒休眠、超过 2 分钟持续待机、断网恢复、第二标签页占用、关闭后不再重连、权限拒绝后可恢复。

先用至少 20 次真人唤醒建立延迟与命中率基线，再确定门限和速度目标。当前尚无这些数据，不承诺固定毫秒数或生产识别率。

## 7. 实施顺序

1. 在独立服务配置并验证“叙华 / 你好叙华”，补长连接、占用控制和识别会话重置。
2. 增加 `/api/wake` 后端代理和 `XfyunWakeWordDetector`，复用 `PersonaBrowserVoiceSession` 与 `PersonaVoiceGate`。
3. 统一麦克风所有权、接入固定应答和音频交接，再加状态提示及浏览器耗时汇总。
4. 单展示终端灰度验收；配置切回原检测器即可回滚。

参考：[讯飞 AIKit Linux 唤醒文档](https://www.xfyun.cn/doc/asr/AIkit_awaken/Linux-SDK.html)。SDK 与桥接服务的当前行为另已通过服务器代码、运行状态和官方录音回调核对。
